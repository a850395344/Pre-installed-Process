# 四轮汽车线束后段预装工艺文件生成器

本地独立软件（Node.js + 浏览器界面，可选 Electron 窗口），**根据客户上传的项目资料**（标准工时 / EBOM / MBOM/Cutting / 工艺图纸PDF）按线束后段预装工艺规则（V2.6.1 摘要）生成预装工艺结构化数据包、预装工艺岗位表与人工核查表。

## 运行

推荐（直接运行打包好的可执行程序，已内置服务与本机界面）：

1. 进入 `D:\分工艺软件\预装工艺生成器（成品）`
2. 双击 `预装工艺生成器.exe`
3. 打开独立窗口运行本软件，无需浏览器、无需装 Node/依赖

开发者 / 调试（浏览器版，需已装 Node）：

```bash
cd D:\分工艺软件\preassembly-src
npm start
```
浏览器访问端口 `data\port.json`（默认 1314）。

## 使用

1. **放入项目资料**（标准工时/EBOM/MBOM 为必填，工艺PDF可选）：
   - 必填项名称前有红色 `*`；缺失时点击任意主流程按钮会弹窗提示 + 未填项红框闪烁，补填后红框消失。
   - 上传文件会暂存到服务端（`data/stash`），点 AI多模态/版本记录/后台数据 或刷新后再返回，文件自动恢复（标注"已恢复"）。
   - 每个已上传文件卡片右上角有 `✕` 可单独删除；文件区有"清空已上传文件"按钮清空全部（不影响你本机原始文件）。
2. 填写工艺参数：
   - **目标节拍 TT（秒/件）**：必填。
   - 制作部位（单选）：车身、仪表、前舱、发动机、四门、顶棚、前后保险杠。**一份MBOM/图纸=一个部位**，部位用于工艺标识与岗位命名，不做按部位过滤、不改变分工艺算法。
   - **最多预装岗位数**：可不填；留空按TT自动算；分析文件后软件会按"最高配置工时 ÷ TT"在输入框给出预计岗位数占位。
   - 预装模式：纯KIT / KIT传递岗+KIT / 纯SUB / SUB+纯KIT / SUB+纯KIT+KIT传递。
   - 是否在线超声波及限制、每个SUB组最多几个预装、打圈工时等（按模式显隐）。
3. 点击 **分析文件**：校验三套模板、输出护套/SP/SC清单、单配置在线超声波组数，并按最高配置工时÷TT 给出预计岗位数。
4. 根据分析结果填写（可留空）：
   - 不能上在线超声波的SP/SC压接点（需热缩管）
   - 强制线下插接完毕的护套
   - 同岗位护套分组（可选）：一组护套=一个岗位，新建一组=另一个岗位；每组可选岗位类型（纯KIT/KIT传递/SUB）。
   - 组超过节拍（TT）的拆分方式开关：①强制同岗（默认）/ ②按最佳插接率拆分；结果输出到"同岗位分组节拍处理"页签与工作表。
5. 点击 **开始解析生成**，查看结果并导出：
   - 预装工艺岗位表 / 人工核查表 / 结构化数据包。
6. 无源文件时可下载标准工时/EBOM/MBOM 模板。

## 关键口径与约定（新AI续作务必遵守）

- **数据只来自客户上传的文件**：配置号、护套、导线、工时、岗位数全部来自页面上传的 MBOM/EBOM/标准工时/PDF；**绝不读取/参考工作目录里的任何项目资料文件**。
- **正式工时只来自标准工时文件**；用户明确提供的固定工时（如KIT打圈 50 秒/件/岗位）除外；禁止经验式虚构工时。
- **岗位数 = 单配置最高工时 ÷ TT**（TT优先；最多岗位数填少会自动扩岗）。单件产品只做一个配置，不叠加各配置工时。
- **制作部位** = 工艺域标识（命名 + 随岗位输出该部位 V2.6.1 工艺要点 + 一致性提示），**不做按部位过滤、不改分工艺（W3/W2 聚合）算法**。
- 岗位级同色线八色编码（PK/RD/OG/YE/GN/WH/VT/BK，无序多色组合，岗位内查重）。
- **维护纪律**：每次功能更新后，务必重新检查并同步"后台数据"页（`version.js` 的 `featureSummary`/`continuationGuide`/`coreFiles`）与 README.md，确保接续信息反映最新状态，便于新AI无损续作。
- 修改代码后用 `node --check` 校验 JS；保持 `server.js`、`src/*`、`public/*` 一致。
- `dist\预装工艺生成器-win32-x64\resources\app` 与 `dist\预装工艺生成器-Dream.zip` 是分发/打包副本；需更新时先关闭正在运行的软件再重新打包（运行时占用文件会导致压缩失败）。
- 继续演进请按 `data/version_history.json` 的版本记录，不丢失已有功能。新AI接续请打开"后台数据"页面复制其内容（含功能一览、续作说明、核心文件说明）。

## 生成内容

- 项目输入资料台账 / 文件模板校验结果
- 总体摘要、文件分析结果、工艺策划参数
- 候选岗位分配（TT优先、自动扩岗）、候选岗位明细
- 预装工艺岗位表（每岗位一个工作表：物料、看板、超声波、插接端、满插、胶带、工时）
- 人工核查表（每岗位一个工作表）
- MBOM导线表 / EBOM物料表 / 标准工时表
- 导线完整路径表 / 护套关联矩阵 / 候选预装工作包（W3/W2/W1候选）/ 孔位责任矩阵
- 同色线编码方案（八色无序标准化）
- 岗位×配置工时矩阵（含TT负荷率）
- **同岗位分组节拍处理**表（超节拍组被拆分或强制同岗）
- **线下插接率与工时**表（整体预装插接端数 ÷ 全束需插接端数，按配置）
- 冲突与待确认事项 / PDF图纸关键词表

## 其他页面

- 检查更新 / 一键更新：顶栏"检查更新"按钮读取 `data/update_config.json` 的 `updateUrl`（Gitee 上 `version.json`）与当前版本比对；有新版时可点"立即下载并更新"（下载 `update.zip` 并 sha256 校验），重启软件后自动覆盖应用源码完成升级。未配置更新源时会给出填写指引。
- AI多模态：PDF 用 `pdf-to-img` 转图片后走视觉模型分批识别（每批≤4张/约8MB，模型按 needMore 决定是否继续，结果自动合并）。
- 版本记录：展示版本历史。
- 后台数据：鉴权后展示功能一览、续作说明、核心文件说明、版本历史、文件清单，供复制给新AI无损续作。

## 在线更新与发布

软件内置"检查更新/一键更新"：顶栏按钮 → `/api/update/check` 读 `data/update_config.json` 的 `updateUrl`（Gitee 上 `version.json`）→ 与 `package.json` 版本比对；有新版可点"立即下载并更新"（`/api/update/download` 下载 `update.zip` + sha256 校验，存待更新目录），**重启软件后** `applyPendingUpdate()` 自动覆盖应用源码完成升级。

发布流程（开发者用）：
1. 编辑 `data/update_config.json`：填 `owner`/`repo`/`branch`（默认分支固定，raw 直链用该分支）。
2. 在 `发布说明.txt`（UTF-8）写本次更新说明（可选）。
3. 运行 `node publish-update.js <新版本号x.y.z>`，例如 `node publish-update.js 1.0.25`。
4. 把生成的 `发布输出\update.zip` 与 `发布输出\version.json` 传到 Gitee 仓库根目录（对应分支）。
5. 使用者点"检查更新"→ 发现新版 → 点"立即下载并更新" → 重启软件 → 自动覆盖源码，升级完成。

注意：更新包**只含源码文件**（server.js、src、public、package 等，排除 node_modules/dist/敏感数据），体积很小，避开 Gitee 单文件限制。

## 技术栈
